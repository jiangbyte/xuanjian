# 玄鉴工程规范

> Author: Charlie

本文约定目录结构、注释、模块边界与禁止事项，供开发与 Code Review 使用。

## 目录约定

| 路径 | 职责 |
|------|------|
| `src/features/*` | 业务功能页与领域组件（hosts / terminal / network / …） |
| `src/components/*` | 跨功能共享壳层与通用 UI（标题栏、对话框、选择器等） |
| `src/lib/*` | 无 UI 的领域服务（DB、Tauri 封装、会话连接等） |
| `src/stores/*` | Zustand 全局状态 |
| `src/i18n/*` | 文案与 i18next 初始化 |
| `src/styles/*` | 全局样式与设计令牌 |
| `src-tauri/src/commands/*` | Tauri 命令薄层（参数校验、状态装配，少写业务） |
| `src-tauri/src/session/*` | SSH / 本地 PTY / SFTP 协议实现 |
| `src-tauri/src/network/*` | 本机网络探测与抓包等 |
| `src-tauri/src/db/*` | SQLite 迁移脚本注册 |

路径别名：`@/*` → `src/*`（**优先使用**，少用相对路径 `../`）。

## 命名约定

- 网络工具子面板：`*Panel`（如 `HttpPanel`）
- 终端侧栏子页：`*Pane`（如 `OverviewPane`）——与 Panel 语义不同，勿随意改名
- Tauri 命令名与前端 `invoke` 字符串必须保持稳定，禁止无兼容期改名

## 注释规范

每个 `.ts` / `.tsx` / `.rs` / 主要 `.css` 文件顶部：

```ts
/**
 * @file 模块中文名
 * @author Charlie
 * @description 本文件职责与边界（2–4 句）
 */
```

Rust 使用模块级文档注释，并写明 `Author: Charlie`。

要求：

- 每个导出函数 / 组件 / 命令：说明做什么、关键入参、副作用
- 文件内逻辑区块用分段注释
- 非显而易见的分支、协议与安全逻辑必须写清原因
- 用户可见文案走 i18n，不要把产品文案只写在注释里

## 模块边界

- UI 不直接拼 SQL；统一经 `src/lib/db`
- UI 不直接散落 `invoke` 字符串；统一经 `src/lib/tauri`
- Rust 命令层不堆协议细节；协议放在 `session` / `network`
- 迁移只放在 `db`，禁止在命令里改表结构

## 禁止事项

- 不改动已有 Tauri 命令名与 SQLite schema（除非单独需求）
- 不引入无必要的多 crate / 前端 monorepo packages
- 不提交密钥、明文密码、本机绝对路径配置
- 不删除或绕过 Windows release 下的 `windows_subsystem` 设置

## CI

本地提交前建议执行：

```powershell
pnpm ci
cd src-tauri; $env:RUSTFLAGS='-D warnings'; cargo check --locked
```

远程：`.github/workflows/ci.yml` 在 push/PR 到 `main` 时跑前端 `typecheck` + `lint` + `build`，以及 Rust `cargo check --locked`（`-D warnings`）。
