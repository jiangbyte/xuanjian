# v1.3.2

桌面运维工作台的一次**聚焦发布**：去掉不够灵活、未形成主线的产品面，保留终端内 Docker 能力与既有性能改进。

## 变更摘要

| 项 | 说明 |
| --- | --- |
| 移除 | 移动端伴侣 UI、Android APK Release 流水线 |
| 移除 | Docker Compose / Dockerfile **编排工作室**（侧栏 `/docker`） |
| 保留 | 终端左侧 **Docker 面板**（容器 / 镜像 / 网络 / 卷 / 实时日志） |
| 保留 | Agent 工具 `docker_ps` / `docker_logs` / `docker_inspect` / `docker_compose_up` 等 |
| 数据 | 迁移 **v28**：`DROP TABLE IF EXISTS docker_projects` |

## 详细变更

### 1. 移除移动端产品线

此前尝试的 Android 伴侣（SSH / 文件 / 笔记壳、Release 并行打 APK）已整体回滚，不再维护：

- 前端 `MobileShell`、移动路由与 `?mobile=1` 调试入口
- `tauri.android.conf.json`、Android 签名 Secrets / CI job
- 相关文档与发布产物中的 APK

桌面四端安装包（Windows / macOS / Linux）发布流程不变。

### 2. 移除 Docker 编排工作室

侧栏「Docker」页（Compose 可视化编辑、Dockerfile Studio、项目模板、导入导出分段）已删除。原因：表单化编排不够灵活，日常更适合在终端 / Agent 里直接使用 `docker` / `docker compose`。

受影响范围：

- 路由：`/docker` 与侧栏入口
- 代码：`src/features/docker/**`、`src/lib/db/dockerProjects.ts`
- 分享导出：不再提供「Docker 工程」分段
- 首次启动示例：不再注入 Docker 示例项目
- 数据库：升级到本版本后自动删除 `docker_projects` 表（不可恢复；请先自行备份若仍需要其中 YAML）

### 3. 仍然可用的 Docker 能力

- **终端侧栏 → Docker**：对接当前会话主机，管理容器并跟随日志（可复制）
- **Agent**：可派发 Docker 相关工具做巡检与 `compose up`（在已打开的会话上执行）

### 4. 继承自 v1.3.1 的改进

若你从更早版本升级，以下内容仍在主干中（详见 [v1.3.1](./v1.3.1.md)）：

- Hosts / Scripts 列表与批量删除性能
- 终端懒挂载 + 重模块预热，多标签状态保留
- SFTP / 进程 / AI 列表虚拟化；AI 消息 memo
- 生产构建修复（`agent-loop-guard` 浏览器兼容）

## 升级说明

1. 安装本版桌面包即可；用户数据目录与 SQLite 库路径不变。
2. 首次启动会跑迁移 v28；若本地曾保存编排工作室项目，表会被删除——需要请先从旧版导出或自行备份库文件。
3. 书签或习惯打开 `/docker` 的用户会被路由重定向到首页；请改用终端侧栏 Docker。

## 安装包

| 平台 | 产物 |
| --- | --- |
| Windows x64 | `*_x64-setup.exe`（NSIS）、`*_x64_en-US.msi` |
| macOS Apple Silicon | `aarch64` `.dmg` / `.app` |
| macOS Intel | `x64` `.dmg` / `.app` |
| Linux x64 | `.deb`、`.AppImage`、`.rpm` |

安装包不含用户数据；首次运行在本机创建空库。Windows 需 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
